## Modules

| Module | What it does |
| --- | --- |
| **Smart Scan** | System junk, developer junk, AI tool data and app caches in one scan — see [Smart Scan in detail](#smart-scan-in-detail). Items (simulator data too) are measured in parallel, so a scan finishes sooner. |
| **Privacy** | Per browser (Safari, Chrome, Edge, Brave, Arc, Opera, Vivaldi, Firefox, and the Beta/Dev/Canary channels of Chrome and Edge and Brave Beta/Nightly, each its own group shown only when installed and skipped while that channel runs): browsing history, download history, cookies, autofill form data (Firefox history and downloads are erased inside places.sqlite; bookmarks are kept; Safari history is skipped while Safari or a macOS service still has its database open). System: recent items, QuickLook thumbnails, shell / REPL / less / Vim history. Nothing is ticked by default. |
| **Large & Old Files** | Files ≥ 50 MB in your home folder — or only in the **Scope** you pick in the toolbar: Downloads, Desktop, Documents, any folder inside your home via **Choose Folder…** (folders outside home, in ~/Library or hidden are refused), or one of the last 5 chosen; the scope is remembered between launches (a folder that is gone or no longer allowed falls back to your home folder); changing it scans again; a folder scope can also go down to **At least 1 MB** or **10 MB** (choosing a smaller size scans again, a larger one only filters; the home folder stays at 50 MB or more), and without Full Disk Access a folder macOS protects shows a request for access instead of being scanned — filtered by size, last use (Spotlight's last-opened date, else last access; a later modification also counts) and kind (video, archive, disk image, installer…), a toolbar search by file name or folder, a **Duplicates Only** filter (files with an identical copy, grouped together with a Copies column; only files of the same byte size are read and compared by SHA-256 (files whose beginning already differs are not read in full, and files are read a piece at a time, so it uses little memory even on very large files; the progress bar always reaches 100%, even if some files can't be read; hashes are remembered between launches, even when you stop the search midway, so unchanged files are not read again), hard links to one file and APFS clones that still share all their data do not count, nothing is ticked for you; **Select Extra Copies** ticks every copy except one per group: the oldest by modification date, ties go to the shortest path, counting copies hidden by other filters too; if every copy of a file is ticked, the Trash confirmation warns that none will be left), a sortable Location column (containing folder, `~` for home), Quick Look with Space, **Select All**/**Deselect All** for the files the filters show, **Show in Space Lens** in the right-click menu. A file that has other hard links is marked **Hard link — moving it frees no space**. Selected files go to the Trash (⌘⌫ or the button, after a confirmation). Folders are read in parallel, so a scan takes about half as long. |
| **Uninstaller** | Apps in /Applications and ~/Applications (including up to three subfolders down, e.g. `Adobe Photoshop 2025/`; never helper apps inside another app) with their data in ~/Library (Application Support, Caches, Preferences, Containers…), plus leftovers of apps already removed. Data is matched by bundle id, and in Application Support, Caches and Logs also by a folder named like the app — its name, its bundle name or executable (`Code` for Visual Studio Code), or that name without spaces or with `-`/`_` (`DiskDrill`, `beekeeper-studio`) — unless another installed app goes by that name too. A folder in Application Support that only starts with the app's first word (`BraveSoftware` for Brave Browser, when no other app starts that way) is listed as **Possibly related**, and the app's config outside ~/Library — `~/.config/<name>`, `~/.<name>` or `~/.<name>-…` (`~/.config/zed`, `~/.cursor`) — is listed too; neither is ticked for you. Config is never shell or login files, keys (`.ssh`, `.gnupg`, `.aws`, `.kube`), `~/.config`, `~/.cache` or `~/.local` themselves, stores shared by developer tools (`.npm`, `.cargo`, `.android`…), a command-line tool's own config (`~/.claude`, `~/.gemini`…), nor a name used by a command-line tool installed outside the app. Each app row shows the app's size and, once measured in the background (all apps at once, so it fills in quickly), the size of its data ("45 MB · data 1.2 GB", the same files its detail lists, unticked ones included; without Full Disk Access Containers and Group Containers are not counted). Sort the list by Name, Size (largest first, app + data once measured) or Last Used (oldest first) from the toolbar, and show only apps not used for over 3 months, 6 months or a year (apps macOS never recorded as opened count as unused; it combines with the search); both choices are remembered. Drag an app onto the window to select it. Untick the app's own row to **Reset** it instead: only its ticked data goes to the Trash and the app stays installed (handy when its settings or cache are broken; quit it first). Right-click a data row and choose **Show in Space Lens** to see it in its folder. Everything goes to the Trash. An app owned by the system or another user (for example from the App Store) goes to the Trash the way Finder does it: macOS asks for an administrator password; if you cancel, nothing is moved and its data stays (putting such an app back with Undo may not be permitted — it then stays in the Trash). **Unknown Hidden Config** lists hidden items in your home folder and items in `~/.config` that no known tool, installed command-line tool or app explains, flagging ones that contain a program/script or changed in the last 7 days — warning only, CleanMate never removes them (Reveal in Finder / Quick Look). **Extensions** lists preference panes, Quick Look plug-ins, services, screen savers, input methods, internet plug-ins and Spotlight importers in `~/Library` (not `/Library`) with their type, size, date and owning app (same bundle id or vendor), marking ones whose app is gone as **App removed** (apps open from outside the Applications folders count as installed). Nothing is ticked for you: tick items and choose **Move to Trash…**; only an item directly in one of those folders, with the right type (`.prefPane`, `.qlgenerator`, `.workflow`, `.saver`, `.app`/`.bundle` input method, `.plugin`/`.webplugin`, `.mdimporter`), not a symlink and not Apple's is moved (checked again right before), and Undo / ⌘Z puts it back. While System Settings is open, preference panes can't be ticked (**Close System Settings to move**, with a **Quit System Settings** button). |
| **Space Lens** | Browse any folder (**Choose Folder…**; the **Location** menu lists the last 5 chosen under **Recent**) sorted by size (measured like `du`) with a donut chart of its contents, drill down (breadcrumb from your home folder for folders inside it, ⌘[ to go back), search the current folder by name (the total and donut still cover the whole folder), Quick Look with Space, move items in your home folder to the Trash (⌘⌫ or the button, after a confirmation). Big folders are measured in parallel, so a scan of your home folder takes about half as long. |
| **Login Items** | Your launch agents with owner app and state: disable, enable or remove (plist to the Trash). The plist's Label is read again right before; if it changed, can't be read or another plist in the folder uses the same Label, CleanMate refuses instead of touching another service. System agents are read-only. |

## Settings, shortcuts and Undo

**Settings** (⌘,): optional menu bar item showing free space and the space freed in the last 30 days (off by default), Full Disk Access status, age thresholds (old logs, temporary files, AI sessions), remembered
choices, updates (see [Privacy](#privacy)), excluded folders, and the activity log. **View** › ⌘1–⌘6 switch modules; **Scan › Scan Again** (⌘R) rescans the visible module and **Scan › Stop** (⌘.) stops a running scan. With VoiceOver, the warning shown when you exclude a broad folder and the confirmation that remembered choices were reset are read aloud, and keyboard focus moves to **Cancel** when a confirmation row appears in Settings. Clean/Trash have no shortcut on purpose, and while a delete or Trash confirmation is open ⌘R, ⌘., ⌘⌫ and ⌘1–⌘6 do nothing.
Before the first scan, Smart Scan shows the free space on your disk and how much CleanMate freed in the last 30 days.
In Smart Scan and Privacy each group header shows its total and a **Select All / Deselect All** button (items that are locked or empty stay unticked) and can be collapsed; arrow keys move between rows and Space ticks or unticks the selected ones. The Uninstaller's file list (leftovers and Reset too) and Extensions work the same way (rows that can't be ticked stay as they are); in Unknown Hidden Config, Space opens Quick Look. After a scan, items in each group are sorted largest first (during the scan they keep a fixed order so rows don't jump). Rows show the app's icon when there is one and a small bar comparing each size with the largest in the group (Large & Old Files, Uninstaller and Space Lens have the same bars); after cleaning, the result lists what each group freed.
After a scan the sidebar shows a badge next to Smart Scan and Privacy (size selected) and Large & Old Files (files found). After moving items to the Trash, an **Open Trash** button opens it in Finder. In Large & Old Files, Space Lens and Uninstaller (also a Reset) an **Undo** button puts the items of that module's last move to the Trash back where they were — only while they are still in the Trash, never over something now in their place, and only if their folder still exists (not replaced by a link, nor by another disk mounted there); anything it can't put back is counted and left in the Trash. Undo lasts until CleanMate quits (nothing is saved). Launch agents an uninstall booted out stay unloaded until the next login. The same undo is also on **Edit › Undo Move to Trash / Undo Uninstall / Undo Reset (⌘Z)**; using either one removes the other, and there is no redo. It is dropped by a new scan, a new move to the Trash, another Space Lens folder, or switching to another module. While typing in a search field, ⌘Z first undoes the typing. Smart Scan has no Undo (most of what it cleans is deleted outright) and no ⌘Z.
Items locked in Finder can't be moved to the Trash: Large & Old Files, Space Lens and Extensions count them separately as **Locked in Finder (turn off Locked in Get Info): N** (a folder that only contains locked files still moves). Uninstalling a locked app says so — select it, choose File > Get Info, turn off Locked, then try again — and nothing is moved, its data included.
CleanMate has a single main window; closing it keeps the app running — click the Dock icon (or **Open CleanMate** in the menu bar item) to bring it back. Quitting (⌘Q or the menu bar's Quit) while cleaning, moving items to or back from the Trash, or changing a login item asks first (**Quit Anyway**; Esc or Return cancels): what was done stays done, the rest is left, and there is no Undo.

Every scan shows its progress and can be stopped with **Stop**, which ends it right away even deep inside a large folder tree; cleaning, once started, is never interrupted. If CleanMate is in the background when a scan or clean finishes, its Dock icon bounces once (no notification, no sound; not after Stop). From the second scan on, the progress bar is based on how long each item (Smart Scan, Privacy) or how many files (Large & Old Files) the previous scan took.

## Smart Scan in detail

**System**
- User caches (a folder named after a running app's bundle ID or name is skipped; generic vendor names such as Google or Microsoft don't count; so is a folder holding a file another process has open, e.g. a CLI daemon; Poetry's project virtualenvs in `~/Library/Caches/pypoetry/virtualenvs` are never removed).
- Caches of sandboxed (App Store) apps inside their containers and of app groups (Group Containers, e.g. Microsoft Office, Slack) — only with Full Disk Access; never Apple's or running apps.
- Copies of attachments opened in Mail — only with Full Disk Access and Mail closed; older than the old-logs age, unticked, moved to the Trash.
- iPhone and iPad backups made by Finder — only with Full Disk Access; unticked, moved to the Trash; each backup listed with its device name and date when expanded, with its own checkbox so you can keep some; skipped while a backup runs or if written to in the last hour.
- Downloaded iOS/iPadOS updates (`.ipsw` in `~/Library/iTunes/iPhone|iPad|iPod Software Updates`, plus Apple Configurator's firmware cache with Full Disk Access) — only `.ipsw` files, each listed with device and version (e.g. "iPhone · 18.1 (22B83)") and its own checkbox; unticked, moved to the Trash; skipped while Finder or Apple Configurator updates a device.
- Old logs, crash reports, old temporary files (an item holding a file a process has open is never old), the Trash (unticked by default).

**Developer junk** (each item hidden when empty)
- **Xcode**: DerivedData (skipped while Xcode or `xcodebuild` runs; each project can be ticked on its own when expanded, shown with its workspace path and last use; shared caches such as ModuleCache are marked "shared by all projects"), device support (each OS version can be ticked on its own, e.g. "iOS 18.1 (22B83)"), old archives (moved to the Trash; each archive can be ticked on its own when expanded), simulators, SwiftUI Previews simulators, simulator caches (skipped while Xcode or Simulator runs), old simulator runtimes (unticked; only a runtime that a newer installed runtime of the same platform replaces and that was not used for 30 days, removed with `simctl runtime delete`; skipped while Xcode or Simulator runs).
- **Package caches**: SwiftPM, CocoaPods, npm, npx (skipped while `npx` runs), nvm downloads (`~/.nvm/.cache`, never installed versions), Yarn (the Yarn Berry global cache `~/.yarn/berry/cache` is a separate unticked item: Plug'n'Play projects need `yarn install` again), pnpm, Bun, pip, uv, Go, Cargo (Cargo, Yarn, Bun and pip caches are skipped while that tool runs), rustup downloads (`~/.rustup/downloads` and `tmp`, never toolchains; skipped while `rustup`, `cargo` or `rustc` runs), Gradle (caches; downloaded wrapper versions unticked), Maven, Homebrew, Composer.
- **Downloaded tools and models**: Puppeteer (unticked; run `npx puppeteer browsers install` to get it back), Playwright, Cypress (unticked), Prisma engines (`~/.cache/prisma`), Hugging Face models, datasets and spaces (only the `models--*`, `datasets--*` and `spaces--*` folders of `~/.cache/huggingface/hub`; unticked, each one can be ticked on its own when expanded and is removed as a whole folder; the login token is never touched).
- **Android emulator** quick-boot snapshots (`~/.android/avd/*.avd/snapshots`; unticked, each snapshot can be ticked on its own when expanded; skipped while an emulator runs; the emulator's disks, SD card and settings are never touched).
- **Old JetBrains IDE and Android Studio versions**: settings, caches and logs folders such as `GoLand2025.3` or `AndroidStudio2026.1.1` in Application Support, Caches and Logs; unticked, moved to the Trash, each version can be ticked on its own; only versions older than the newest of the same product, never the newest one nor folders without a version; skipped while a JetBrains IDE or Android Studio runs. User caches and Old logs leave these IDE folders, including the current version's caches, to this item.
- **OrbStack**: the app's caches (including its downloaded updates) and logs (`~/Library/Caches/dev.kdrag0n.MacVirt`, `~/.orbstack/log`); skipped while OrbStack or its VM manager runs, and a log still open is kept; machines, containers, SSH keys and settings are never touched.
- **Docker** (only when a local daemon is already running; commands always target a local socket — the current context's when it is local — never a remote context): build cache; unused images, stopped containers and unused volumes (unticked). Expand an item to see exactly what its prune command would remove — view only, each item is cleaned as a whole: each image (name or ID, size, date), each stopped container (name, image, status, size), each unused volume (name, driver, size; anonymous ones marked; named volumes too), each build cache record (ID, type, description, size, last used; records shared with an image are marked as freeing no space).
- Go, npm, pnpm and uv caches moved in the tool's own config (`go env -w`, `.npmrc`…) are found by asking the installed tool. Folder variables set in your shell profile (`NVM_DIR`, `RUSTUP_HOME`, `CARGO_HOME`, `GRADLE_USER_HOME`, `HF_HOME`, `HF_HUB_CACHE`, `ANDROID_AVD_HOME`, `ANDROID_EMULATOR_HOME`, `OLLAMA_MODELS`) are read from `~/.zshenv`, `~/.zprofile`, `~/.zshrc` (in that order, later wins), then `~/.profile` and `~/.bash_profile` for variables zsh leaves unset. The files are only read, never run: just top-level `export VAR=value` lines with a literal value (`~`, `$HOME` allowed, plus `$XDG_DATA_HOME`/`$XDG_CACHE_HOME`/`$XDG_CONFIG_HOME` and the variables above when set earlier by such a line, the XDG ones defaulting to `~/.local/share`, `~/.cache`, `~/.config`); anything using `$(…)`, backticks, `${VAR:-…}`, other variables or inside an `if` block is ignored. The folder must exist inside your home; it is scanned in addition to the default one.

**AI tools**: caches, logs and old sessions of Claude Code, Claude Desktop, Codex, Gemini CLI / Antigravity, Cursor, Windsurf, Zed, Orca, Copilot CLI, Continue, Ollama, LM Studio. Old sessions can be ticked one by one; Claude Code ones are named after their project path (`~/Developer/app`, or the raw folder name when the project no longer exists).
- **Orca**: only its Electron caches, crash reports and logs; skipped while Orca or its terminal host runs. Accounts, keys, profiles, terminal history and the session index are never touched.
- **Ollama models** (`~/.ollama/models`, or `OLLAMA_MODELS` from your shell profile): unticked; each model is listed by name (`llama3.2:latest`) with the date it was pulled and can be ticked on its own. Removing one deletes its manifest and the blobs no other model uses, like `ollama rm`; layers shared with another model stay (and count in neither size). Skipped while Ollama runs. Downloaded again with `ollama pull`; a model made with `ollama create` must be made again. The Ollama key is never touched.

**Apps**
- Caches of browsers (including the Beta/Dev/Canary channels of Chrome and Edge and Brave Beta/Nightly, each skipped while that channel runs), VS Code, Slack, Discord, Zoom, Spotify, Notion, Figma and more.
- On-device AI models of Chrome (`OptGuideOnDeviceModel`) and Edge (`EdgeLLMOnDeviceModel`), every channel; unticked, the browser downloads it again when an AI feature is used; skipped while that channel runs.
- Google Updater's downloaded update packages (`GoogleUpdater/crx_cache`; skipped while the updater runs; the updater itself, its settings and logs are never touched).

**How it cleans**
- Ticking only some backups, archives, DerivedData projects, device support versions, models or snapshots makes the item's checkbox mixed and its size column shows "selected / total"; those per-entry ticks last until the next scan and every entry is listed (no cap). VoiceOver reads each entry as its label, date and size, not its long path.
- Official tool commands (`npm cache clean`, `brew cleanup`, `go clean`, `simctl`…) are used when installed.
- Sizes are what the command really frees (`brew cleanup --dry-run`, `docker system df`); pnpm has no dry run, and Bun and uv share files with your projects as APFS clones, so their sizes are shown as "Up to …" and kept out of the sure total; what they really freed is measured from the disk's free space. Homebrew's size is reused from the last scan while its cache, Cellar and Caskroom are unchanged (up to 6 hours).
- A file with several hard links in one item is counted once, so sizes match `du -sk`; an item with a subfolder CleanMate can't read says **Some items could not be read — the size may be larger**.
- Files and folders that are locked or protected by macOS (e.g. the empty `com.apple.*` folders in the temporary folder) are never listed: removing them could only fail.

## Safety

- **Preview, then confirm.** Every module lists what it found with sizes; nothing is removed until you confirm.
- **Trash vs delete.** Regenerable data (caches, logs, developer junk) and privacy traces are deleted. User files,
  apps, app data, old AI sessions, old Xcode archives and launch agents are moved to the Trash, so you can put them back.
- **Your choices stick.** Items you untick stay unticked on the next scan (Settings › General › Remembered choices › **Reset…**, which asks before forgetting them).
- **Turn off whole groups** (Settings › Scan Groups): a group switched off there (for example Developer Junk or AI Tools) is not scanned nor shown, so Smart Scan finishes sooner; the results say how many groups are off, with an Open Settings button. With every group off, Scan is disabled. Privacy has no such switch (its few browser groups are quick to scan and nothing is ticked by default).
- **Hard blocklist**, checked when scanning and again right before every removal: only paths inside your home or
  temporary folder; never `.ssh`, `.gnupg`, `.aws`, `.kube`, Keychains, Documents, Desktop, Pictures, Movies,
  Music, iCloud Drive, CloudStorage, Mail, Messages (Large & Old Files and Space Lens only touch what you pick, and
  only to the Trash). Never another volume mounted inside your home (e.g. a connected iPhone's file system in
  `~/Library/Developer/CoreDevice/DeviceFS`, a network share): it is neither measured nor removed, and no module moves to the Trash or deletes a folder that has one mounted inside it. Never passwords, bookmarks, extensions, sign-ins, settings or AI memory.
- **Exclusions** (Settings › Exclusions): nothing inside an excluded folder, nor an excluded file, is ever listed or removed by any module, and its parent folders are never removed either. Add folders with **Add Folder…**, drag folders or files from Finder into the list, or right-click a path in an expanded Smart Scan/Privacy item, a Large & Old Files row or a Space Lens row and choose **Never Clean This** (packages such as .app and symlinks can't be excluded). The row then leaves Smart Scan and Large & Old Files; Space Lens keeps showing it but won't move it to the Trash. Tool commands (npm, pnpm, uv, go, brew, simctl) can't honor exclusions, so a Smart Scan item cleaned by command whose folder contains, is inside or is an excluded folder is shown unticked and locked with **Blocked by a folder in Exclusions** and a button to the Exclusions settings. Excluding your home folder, `/` or a folder that holds them asks first (**Add Anyway**), since CleanMate would then clean nothing; **Never Clean This** never excludes them.
- **Running apps** are skipped; quit them first. Caches and temporary files that a running process has open are skipped too (checked again while cleaning). Old sessions of Claude Code, Codex, Gemini CLI and Copilot CLI are also skipped while that command-line tool is running (detected by process name, and by install path for npm installs and wrapper scripts, e.g. `node …/@anthropic-ai/claude-code/cli.js`).
- **Only your user account.** No administrator rights, no privileged helper, no system files. The one exception is moving an app owned by the system or another user to the Trash, where macOS itself asks for the password, as in Finder.
- **Activity log.** Every removed item is recorded (date, module, item, count, size, deleted/trashed/restored — restored = put back by Undo, no longer counted as freed) in
  `~/Library/Logs/CleanMate/activity.log` (rotated at 1 MB), viewable in Settings › Activity as a table (newest first; filter by module or search item names and paths), which also totals the space freed (last 30 days and overall; items moved to the Trash are counted separately).
  Module and item names are stored in English and shown in the current app language.

## Permissions

- **Full Disk Access** (optional): needed to read the Trash, Safari data and some app containers. CleanMate offers
  it once at first launch; you can skip it and grant it later in System Settings › Privacy & Security ›
  Full Disk Access.
- Without Full Disk Access, Large & Old Files and Space Lens do not look inside the folders macOS guards with a
  per-folder prompt (Desktop, Documents, Downloads, Movies, Music, Pictures, iCloud Drive, CloudStorage, other apps'
  containers — list in [`ProtectedFolders.swift`](../CleanMate/CleanMate/Engine/ProtectedFolders.swift)), so no access dialogs pop up; a note with an Open Settings
  button says some folders were skipped.
- **App Sandbox is off**: a cleaner must read and remove caches of other apps and developer tools across your home
  folder, which a sandboxed app cannot do. Hardened Runtime is on. CleanMate is distributed outside the Mac App Store
  (Developer ID, notarized).

## Privacy

CleanMate collects no data: no analytics, no telemetry. Its only network connection is the update check, done with
[Sparkle](https://sparkle-project.org):

- **CleanMate › Check for Updates…** checks now. Automatic checks are off on the first launch; on the second launch
  CleanMate asks whether to check automatically (and whether to download and install updates by itself).
- **Settings › General › Updates**: **Automatically check for updates** and **Automatically download and install
  updates** (only with automatic checks on) change that answer at any time.
- A check downloads the update feed (`appcast.xml`) from this project's latest GitHub Release; the update itself is
  downloaded only when you install it or allow automatic downloads. No system profile or other data is sent.
- Every update is signed with the project's EdDSA key and checked before it is unpacked; macOS checks its Developer ID
  signature and notarization as for the first install.

Settings are stored in the app's own preferences on your Mac.

## Languages

English (default) and Vietnamese, following your system language. To use another language for CleanMate only:
System Settings › General › Language & Region › Applications.
